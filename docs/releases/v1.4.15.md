# Rune v1.4.15

A patch on v1.4.14, found by Rune's live run on its own source. `done` now counts only real
failures, so a careful run, one that investigates a failure before it finishes, can end `done`.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

On the live re-run of the dogfood task on 1.4.14, every end-of-turn check passed on Rune's own
source (the full suite, lint, the format check, typecheck) and the request check found 13 of 13
asks. `done` was still refused. The agent had seen a test fail inside its sandbox, and it did
the careful thing: it built a copy of the repository to show the failure was not its own, ran
the test there, and probed for the copy with `test -d` before removing it. Every one of those
was logged as a failed project check. `done` now counts only real failures:

- **A probe is not a check.** The shell's own `test` and `[` ("does this file exist?") no longer
  count as project checks. A script named `test` (`./test`, `scripts/test`) still does.
- **A run in a copy of the project is not the project's check.** A `bun test` run whose files lie
  outside the workspace, or in a folder git tracks nothing in, and which mirror the project's
  own paths (`.copy/tests/unit/a.test.ts` holds `tests/unit/a.test.ts`), is an action, not a
  check. A new folder of new tests mirrors nothing and stays the project's; so does a package
  whose layout mirrors the root's, because its folder is tracked.
- **A red file the passing suite also ran is covered.** Rune reads what its own test suite runs
  from the suite's script. When that suite passed on the final tree and ran the file a red run
  named, the red run no longer refuses `done`, and the verdict names it: "an earlier red test run
  is covered by the suite that passed". A run after a `cd`, a file outside the suite, or a
  command that cannot be read is not covered.

Anything else the run saw fail still refuses `done`.

## Checked, and stated

- **Replayed on the 1.4.14 run's own record:** `done`, with the covered run named. Without the
  suite's scope, the same record stays `unmet`.
- **Through the real engine** (`tests/integration/done-long-suite-e2e.test.ts`): an agent that
  sees a test fail, re-runs it in a copy, probes with `test -d` and then fixes it ends `done`. A
  red test in a new folder of new tests still refuses `done`.
- **15 deliberate breakages, all caught**, across the three rules and their wiring. One survived
  at first: a `cd` into a folder whose path lines up with the root's would have read as covered.
  A test now pins it.
- **Suites:** unit 8,118 passed and 0 failed; integration 497 and 0; reliability 62 of 62; the scripted evaluation 63 of 63; typecheck 15 of 15; lint 7 of 7.
- **CI caught a Windows bug in the first release commit.** On Windows a copy on another drive
  than the workspace (the runner's checkout is on D:, its temp folder on C:) read as inside it,
  so it was not recognised as a copy. Fixed, with a test that reads paths by Windows' own rules.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows.

## Known, and stated

- **`done` on Rune's own source is not yet shown live.** The re-run on 1.4.15 waits for the
  Codex quota.
- **Only `bun test` runs are read** as copies or as covered. Another runner's red run still refuses
  `done`, as before.
- **A check's limit counts wall-clock time,** so a Mac that sleeps during the end-of-turn check
  turns the sleep into a timeout. Not addressed here.
