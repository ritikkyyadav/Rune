# Rune v1.3.0

Runs that come back. Long headless runs on free tiers die at quota walls, and the author's own
died that way at least three times. A run can now be told to come back: wait for the provider's
window, continue the same session, and stop at a deadline, a budget or a resume count you set.

This release also tries a new way of finding bugs with few users. Another coding agent publishes
what it fixes. 3,338 of those fixes were sorted into failure types by mechanism, and the three
most frequent types that also apply to Rune were probed with zero-spend tests. Every one found
real defects in Rune, and they are fixed here. The method is in
[`docs/program/changelog-mining.md`](../program/changelog-mining.md).

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **Missions.** `rune -P "…" --resume-until 8h` opts a headless run in. When a provider stops it
  (a quota wall, a plan limit, a provider that went away), Rune waits for the provider's own
  window, or backs off from 5 minutes to a 4-hour cap, and continues the session. It stops when
  the task is done, the deadline passes, `--resume-budget` dollars are spent, or `--resume-max`
  resumes are used. It also stops at something only a person can fix, such as a rejected key.
  The plan lives in `rune.db`, so a closed terminal loses nothing: `rune missions run`, called by
  cron or launchd, picks it up. One plan is resumed by one process, and
  `rune missions cancel <id>` holds against all of them. Details: [`docs/missions.md`](../missions.md).
- **Terminal.app.** In macOS Terminal.app the pinned header slid down the window, the footer
  dropped off the bottom, and the mouse wheel never moved the transcript. Terminal.app turns the
  wheel into arrow keys only for a program in application cursor mode, the mode `less` and `vim`
  use. Rune now sets it while it runs, resets it on exit, and no longer erases the display on
  entry. Ghostty, Warp and other terminals are unaffected.
- **Auto's recursive-delete check reads what a delete reaches.** Several spellings went unscreened:
  `rm -fr`, `-r -f`, `--recursive`, a `..` escape, the workspace itself or its `.git`, and a
  target only the shell knows (`$TARGET`, `xargs rm -r`). Outside the workspace halts. The
  workspace, its history or an unresolved target waits for you with the exact next step. Build
  output stays ordinary. Discarding uncommitted work (`git checkout -- .`, `git restore .`,
  `git clean -f`) stashes it first, as a hard reset already did. Windows drive-letter and UNC
  paths are recognised, the gap v1.2.0 listed as open.
- **`config.toml` is read as real TOML.** A list written over several lines used to become the
  string `"["`, so its rules were dropped without a word. That included a multi-line `denyRead`,
  `denyRules` or `excludedCommands`. Quoted values lost everything after a `#`, quoted list items
  split at their commas, and Windows paths came back with doubled backslashes. A file the parser
  refuses still applies what it can, and now says so. If you wrote any list over several lines,
  it takes effect with this release.
- **Background shells end with what started them.** When an engine closes (a session ending in
  `rune serve` or over ACP, or Rune exiting), the background shells it started stop too. A stop
  escalates to a hard kill after a two-second grace, so a process that ignores the polite signal
  no longer outlives it. A stop only ever reaches a process group that is still the shell's.
- **Rune Mono.** The chrome is black and white, with a matte finish by default and a crisp one
  beside it. Every list uses one full-width selection bar. The header is quieter and the idle
  frame is empty. The status line shows the gear, the model and only the keys that act now.
- **Self-evolution keeps its evidence honest.** A learned lesson can never advise leaving
  containment. A mock win, an unknown cost, an outage or a repeated look at an answered question
  cannot promote a change. Lesson trials restart at each release line, including this one.

## Measured

- Unit tests 6,275 pass, 0 fail, 1 skip. Integration 389 pass, 0 fail, 7 skipped for toolchains,
  servers or credentials the machine lacks. Typecheck and lint are clean, and so are the Rust
  crates' tests.
- Each fix was first reproduced by a test that failed. For the process-group rule and the
  missions lock, every part of the rule was also broken on purpose to confirm a test catches it.
- The offline Auto-mode safety corpus (no model, no network) is unchanged by the delete-check
  work: precision 92.8%, recall 89.1%, and 116 of 116 ordinary allowed commands still run.

## Platforms

Windows remains a **preview** with no OS sandbox, so Auto treats every Windows shell command as
uncontained. Two sandbox tests that assert unix-only features are now limited to the platforms
that have them.

## Unverified, and stated

- Missions have run on a fake clock, including a 48-hour night of repeated walls, but not through
  a real overnight run against a real provider. A laptop asleep counts as time passing.
- The Terminal.app fix was checked in a pseudo-terminal at 162×48 and by the author in
  Terminal.app. Other terminals that ignore alternate-scroll mode are untested.
- Two config-loading items from the changelog study remain open: special object keys, and a
  config path that is not a regular file.
- An independent review pass over this release's fixes has not run yet. The author's own checks
  of those fixes found two defects before release, both fixed here: the process-group rule and
  the missions lock.
- Self-evolution's controls are tested, but no live A/B comparison has run, so no improvement is
  claimed.

Everything else is as in v1.2.0.
