# Rune v1.4.12

A patch on v1.4.11. Finished work now says so. A run that did what you asked ends `done`, after
Rune has read the change against your request. One that missed part of it is told what is
missing and finishes it, or names it.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **`done`: finished work says so.** Until now every finished run ended `unmet` ("no criteria
  stated") or `partial` ("no check bound"). That happened even when the work was right: all
  fourteen live runs of 21 October ended that way, and so every benchmark read Rune as
  unfinished. A run now ends `done` when all of these hold:
  - it finished on its own and changed files;
  - the project's own checks passed on the tree it left;
  - no planned step is open and nothing was seen to fail;
  - the request check found every ask of your request in the change.

  `done` produces `ok: true`. `met` is unchanged, and still needs every criterion shown by a check
  bound to it.

- **The request check.** At such a finish, one call on the session's model reads your request
  beside exactly what the run changed:
  - each file Rune's tools wrote, from what it held before the run to what it holds now;
  - files a shell command changed, by name;
  - the checks Rune watched pass.

  Your own uncommitted work from before the run is never shown as the run's. The checker lists
  every ask, found or not. An ask it does not find buys one re-prompt naming it. Still missing,
  it is a gap named `the request`, and the run ends `partial`. A check that cannot answer — a
  change over 120,000 characters of diff, a reply that is not the JSON asked for — leaves the
  verdict as it would have been. Its calls are filed as Rune's own cost (`request_check`).

## Checked, and stated

- **Why the check exists.** On the offline corpus with the end-of-turn check on and no outside
  acceptance, a `done` resting on the project's checks alone called every one of 19 wrong or
  half-done code runs finished: a forgotten changelog, an exporter never touched, a guard
  dropped, a parser right only on its own test.
- **Measured live** (Codex, `gpt-6-sol`, about 30 small calls per series):

  |                                          | Checks alone | With the request check |
  | ---------------------------------------- | -----------: | ---------------------: |
  | Wrong or half-done code runs said `done` |     19 of 19 |            **0 of 19** |
  | Correct code runs said `done`            |       8 of 8 |             **6 of 8** |

  Each wrong run was caught with its reason, in the checker's words: "export-csv.ts is not
  changed", "server.ts returns the plain text body", "money.ts is changed to accept three
  decimal places", "window.test.ts was edited to expect…". The two correct runs it held back miss
  asks the hidden tests do not cover. The corpus's own solution reads `+2` as a word although the
  request says "optionally signed". In the other, the request asked for tests of a migration and a
  CLI, and the change has neither. In a real run each would buy one repair turn.

- **The first live series found a flaw in the prompt, fixed before this release.** The checker
  was shown only the diff, so "add tests and run them" read as not done on six of the eight
  correct runs. It is now given the checks Rune watched pass.
- **18 deliberate breakages, all caught.** They include `done` without the request check; a missing
  ask not turned into a gap; `met` ignoring it; no re-prompt; an unbounded one; the check asked
  when the project's checks were red; the person's old edits shown as the run's; a partial diff
  checked as whole; and files a shell wrote left unnamed. Two first survived, and each got the
  test that catches it.
- **Through the real engine** (`tests/integration/request-check-e2e.test.ts`). With your
  uncommitted edit on disk, the checker saw only the run's change: the edit was not shown and the
  file was not named. A missing ask was re-prompted, finished and then `done`. A file a shell
  command wrote was named.
- **Suites:** unit 8,046 passed and 0 failed; integration 492 and 0; the reliability suites 19 of 19; the scripted evaluation 63 of 63; typecheck 15 of 15; lint 7 of 7.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows.

## Known, and stated

- **One more model call per finished run** that changed code, on the session's model; a few
  thousand tokens for a typical change.
- **The checker is a model.** It is stricter than the hidden tests in places. One of its readings
  in the corpus — a CLI the request said to keep, called missing because the change did not touch
  it — was over-strict. Its cost there is one repair turn, not a wrong verdict.
- **Questions, reviews and plans** change no files and never reach `done`. Their verdicts are what
  they were.
