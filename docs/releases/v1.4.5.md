# Rune v1.4.5

A patch on v1.4.4, and the fourth phase of the reliability plan: what stops a run. A safety block
now stops the action, not the run, and the turn ceiling is the person's to set.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **A safety block stops the action, not the run.** Between 14 September and 14 October Auto mode
  ended three runs. None of them had read anything injected:
  - a `pip install --break-system-packages`, where the reviewer refused 2 actions in a row;
  - an `npx` fetch for a video task, where it refused 2 in a row;
  - a recursive delete outside the workspace.

  A run now ends on safety grounds only when a tool result in its session was flagged as likely
  prompt injection. That is evidence the run may no longer be the person's, and it carries to
  later runs of the same session, because the injected text stays in the transcript. Without it:
  - the action is not run, the agent is told why, and the run goes on;
  - an attack shape (exfiltration, a credential in an outbound payload, host destruction) is
    blocked every time, and is never held or offered to anyone to run;
  - after 3 refusals in a row (it was 2) or 20 in a run, the next blocked action is held on the
    end-of-turn list, where you can run exactly it.

  Auto mode still never opens a prompt mid-run. The reviewer's denials still make every later
  review in the run more careful, but suspicion is not evidence. The screen says `blocked` for an
  action that stopped while the run went on, and `run halted` only when the run ended.

- **The turn ceiling is yours to set.** Five runs in that month ended at 80 turns, and one long
  plan collapsed against the ceiling. Now:
  - an interactive session has no turn ceiling, unless you set `[reliability] maxTurns`, or set
    `/config turns` to a number (or to `0` or `none`);
  - a headless run keeps 80 by default;
  - `rune -P` takes `--max-turns <n>` (0 for none) and `--max-budget-usd <usd>`, and a bad value is
    a usage error (exit 2) before anything runs.

  What looks at what the turns actually do all stays: the loop detector, the barren-turn breaker,
  the outage clock and the budget.

## Checked, and stated

- Every way a run used to halt has two tests: one where the session read a flagged tool result
  and the run halts, and one where it did not and the run goes on. That covers the supervisor's
  objection, the reviewer's streak, and the broker's attack shapes, at the unit level and through
  the real engine and agent loop together.
- **23 deliberate breakages, all caught.** These included:
  - every run treated as captured, and no run treated as captured;
  - a flagged result not counted as evidence, or not carried to the next run;
  - an attack shape held for the person;
  - the limit asking instead of holding;
  - an interactive session keeping its ceiling, or a headless run losing its own;
  - `0` refused by `/config`.
- A run with no ceiling was driven for 95 turns and ended on its own answer.
- Auto mode's never-asks matrix (3 sandbox modes × 2 machines × 4 reviewer behaviours, every shape
  of action) still records no prompt.
- **Suites:** unit 7,907 passed and 0 failed; integration 486 and 0; the scripted evaluation 63
  of 63.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows.

## Known, and stated

- **The loop detector and the barren-turn breaker still end a run.** The plan had them advisory.
  In an interactive session, ending hands the turn back to you, and you can say "continue". In a
  headless run they are what stops a run repeating itself until its ceiling. Neither has fired
  since 14 September.
- **Editor sessions** (`rune engine-host`) keep the default ceiling; only the terminal session
  changed.
- **No live run has exercised this yet.** The record above is from runs before this release; the
  live sitting (R8) is where it is measured.
- The reviewer already never saw tool output, and plain reads and workspace edits already skipped
  it, with `.git`, `.github`, `.rune` and credential files still reviewed. That half of the plan
  needed no change.
