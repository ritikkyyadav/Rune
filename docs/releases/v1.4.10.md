# Rune v1.4.10

A patch on v1.4.9. A background shell started outside the sandbox no longer inherits Rune's
whole environment. Found while preparing the reliability plan's live runs, before any of them
started.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **An uncontained background shell gets what a foreground command gets, and nothing else.**
  Every foreground command goes through `rune-tools`, which clears the environment and passes on
  `PATH`, `HOME`, `TMPDIR`, `USER`, `LANG`, `TERM` and `SHELL`, sandboxed or not. A contained
  background shell got the same from the planner. A background shell started outside the sandbox
  (`unsandboxed: true`, which the shipped defaults allow; the sandbox off; or an excluded
  command) inherited everything Rune had:
  - the provider keys the launcher loads from `~/.rune/.env`;
  - the variables that name the session's database and the person's saved sign-ins.

  A project whose tests write to the credential store those variables name would write into the
  real one. Rune's own repository is such a project, and the reliability plan's live runs work on
  copies of it with those variables pointing at the founder's own files. The founder's record
  holds 266 background shells since July. Five asked to run outside the sandbox (15 September,
  10 October), and any started while the sandbox was off ran outside it too. Whether one of them
  wrote to a credential store is not known.

  It now gets the foreground's list, plus `RUNE_WORKSPACE` and `NO_COLOR`, as `rune-tools` gives.
  A test reads the Rust list and fails if the two ever differ.

- **`rune-baseline`, a second Rune arm for the parity runner.** One series can now pair two Rune
  builds, each from its own `--rune-bin` / `--rune-baseline-bin`, on the same shipped defaults.
  The live proof pairs the last release before the reliability plan with this one.

## Checked, and stated

- **Three deliberate breakages, all caught:** the uncontained shell inheriting again (the shell
  printed the planted credential path and key); the baseline arm taking an effort; its plan named
  `rune`.
- **The record, read-only:** 266 background shells in the founder's `rune.db` since July, five of
  them asked to run outside the sandbox.
- **Suites:** unit 7,987 passed and 0 failed; integration 488 passed and 0 failed; the scripted evaluation 63 of 63;
  the reliability suites 19 of 19; typecheck 15 of 15; lint 7 of 7.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows.

## Known, and stated

- **Other programs Rune starts keep their environment:** MCP servers, language servers and the
  dashboard opener. They are programs the person configured, not commands the agent wrote.
- **The end-of-turn check already ran with a cleaned environment** (v1.4.2). Builds before that
  one hand the check the session's state, and are not run on copies of Rune's own repository.
