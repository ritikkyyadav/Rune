# Rune v1.3.3

A patch on v1.3.2. One fix to Rune, and the first release whose tests ran on Linux and Windows
before it shipped.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **A failing test in a file the run edited is the run's, in GitHub Actions and on Windows too.**
  When a check goes red, Rune separates a failure that was already there from one the run made,
  and a test in a file the run changed always counts as the run's. In two places that last rule
  did not hold. Inside GitHub Actions and on Windows, Rune misread the test file's name in Bun's
  report, so the name matched no changed file. A failing test the run had edited was called
  "already failing", and when it was the only failure Rune asked for no repair. The check was
  still reported red. If you run Rune in a workflow or on Windows, upgrade.

Nothing else in Rune changed. The full list is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Checked, and stated

- **The tests now run on all three systems.** CI had failed on every run on record since late
  September, and 1.3.2's new tests had only ever run on a Mac. Thirty-nine of them failed on Linux
  or Windows: eight because of the fault above, the rest because of assumptions in the tests — `/`
  in paths, a `#!` script, LF line endings, a `rune-tools` on the path, a Chromium in the home
  folder.
- **Four tests depended on the clock**, and each failed once on a CI runner: a delete that did not
  delete, a count that batching changes, and two five-second limits around real builds. Each was
  fixed at its cause, and every test now has thirty seconds unless it sets its own limit.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows.

## Known, and stated

- **A headless run does not wait for its background reviewer.** In Auto mode, ordinary actions
  run and are reviewed in the background. `rune -P` exits when the run is done, so an action still
  waiting for that review is never read, and its audit row still says "allowed under
  supervision". With a reviewer scripted to take 400 ms, a script of five quick commands had one
  shown to the reviewer. An interactive session stays up and hears the verdict. The mechanical
  checks run on every action either way. This is not changed in 1.3.3.
- On Windows, Rune cannot yet rebuild the tree a run started from when the project has installed
  dependencies or other git-ignored files to carry over. It says the answer is unknown there; it
  does not guess.
- Nothing was measured in a live run for this release. The standing against OpenCode, and the
  list of unverified changes, are as stated for
  [v1.3.2](https://github.com/ritikkyyadav/Rune/releases/tag/v1.3.2).
