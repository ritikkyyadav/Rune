# Rune v1.3.2

A patch on v1.3.1. Rune's own checks stop leaving build files in your repository and stop calling
a slow test suite a failed one. Sub-agents can be opened and watched. A run that is killed, or
whose provider goes quiet, ends cleanly and can be resumed.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **Rune's checks leave your tree as they found it.** After a turn, Rune runs the project's own
  checks. In a turbo workspace `typecheck` builds every package, and one run left 129 git-ignored
  files behind. When a pass of checks Rune chose ends, the git-ignored paths it created are
  removed. A folder that was already there keeps what the check put in it; a new file git does not
  ignore is left for you to see; `node_modules`, virtualenvs, `.env*` and editor folders are never
  taken; a command you wrote in `[verify] commands` keeps what it builds. To turn it off, set
  `[verify] keepGenerated = true`.
- **A check that ran out of time is not a failed check.** Verification is now passed, failed or
  inconclusive. A timeout, a cancel or a missing toolchain no longer sends Rune to "repair" working
  code. A project's own `test` script is what runs, a test that was already failing is named and
  left alone, and a TypeScript change no longer runs the Rust checks beside it.
- **Sub-agents can be opened and watched.** With the composer empty, the right arrow steps onto the
  agent blocks on the working row and enter opens that agent's transcript, live. Finished agents
  stay readable, including after a restart.
- **The working row shows what the turn is doing.** One mark, struck by the run's own output, with
  the stage, the current action and the step. The tab's working mark is a pill paced by the work.
- **A run stops cleanly.** `kill`, a closed terminal or a shutdown now stops the commands Rune
  started, records the run as interrupted and exits with the signal's code; the next run of that
  session continues it. A provider that stops answering ends the run after ten minutes with the
  work kept. A provider cap waits until the moment the provider named.
- **`bun add` works in the sandbox.** Once a call has network, an install no longer fails with
  "unable to write files to tempdir". Bun's cache is kept inside the project.
- **The Auto-mode reviewer has thirty seconds, not twelve.** Its ordinary latency was within a
  second of its old limit, so a slow provider meant a refused command.
- **A headless run's exit code follows its verdict.** `rune -P` exits 1, with `ok: false` in the
  JSON envelope, when a change did not meet the terms it was held to: the run stated what done
  means and changed files, or was held to an `--acceptance` check, and the verdict is `partial` or
  `unmet`. A greeting, a question and a review that changes nothing are judged by whether they
  ran, as before.
- **The instructions sent with every request are about a third shorter.** 7,807 tokens to 5,402.
- **Signing in with a Claude Pro or Max plan is removed.** Anthropic's terms do not permit it.
  Claude models still work with an API key, through Bedrock and through Vertex.

The full list is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Measured, and stated

This release was measured against OpenCode on one model (`gpt-6-sol`), with the same tasks and the
same graders. The record is in `docs/program/rune-parity-progress-ledger.md`.

- **Small and medium tasks: a tie on correctness.** Eighteen pairs over nine tasks; both tools
  finished all eighteen, cleanly. Rune was slightly faster and cost about 1.56 times as much at
  list price. That sitting ran before the changes listed as unverified below, the shorter
  instructions among them.
- **One hard task: lost twice.** Rune passed every hidden check and broke one existing behaviour,
  the same one both times. The other tool did not.
- **Not measured:** frontend, review and long-context tasks, and hard tasks beyond that one.

## Unverified, and stated

- These changes passed their tests and have not been measured in a live run: the shorter
  instructions, the exit code that follows the verdict, the reviewer's longer deadline, the
  read-back's wording, `bun add` in the sandbox, and the session cache key.
- A run that states what done means, changes files and proves only part of it now exits 1. That
  is the intent, and it is strict: a script that treated any finished run as success will see
  failures it did not see before.
- The removal of generated files cannot tell a check's output from something else that first
  wrote a git-ignored path in the same seconds — a watcher the run started, or a second agent in
  the same folder. `keepGenerated` is the switch.
- Each later check in a session rebuilds what the earlier one built and removed: about four
  seconds on Rune's own repository.
- Rune's end-of-turn check still runs a project's whole test script under a 120-second limit. On
  a large suite it measures nothing and costs two minutes.
- The new tests ran on macOS. The Linux and Windows jobs are CI's to run.

Everything else is as in v1.3.1.
