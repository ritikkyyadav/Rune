# Rune v1.2.0

Auto mode stops asking. It was designed on 2026-08-28 to never put a permission prompt in
front of anyone — the agent works, attack shapes halt the run, and the few steps only a person
can decide wait in one list at the end of the turn. On the author's own machine it kept
interrupting anyway. The session database said why: every Auto prompt recorded since the
redesign was a shell command with no OS sandbox under it, and none of them was dangerous —
`cargo test`, `make dev-web`, `ps | head`, a `test -f` check. Three causes, all fixed.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **The macOS sandbox works again on macOS 27.** Rune decided whether a Mac could isolate by
  running `sandbox-exec -n no-network true`. macOS 27 retired that named profile: the call is
  killed (exit 137) while an inline profile still applies. Rune therefore concluded the machine
  had no sandbox and ran every command directly on the host, whatever `/sandbox` said — and the
  live Seatbelt tests, which skip when the probe says no, stayed green. The probe now uses the
  inline form the sandbox itself runs with, and a test fails whenever the two disagree. Checked
  live on macOS 27.0: a write inside the workspace succeeds, a write to a sibling folder under
  the home directory is refused, and network is off unless a command asks for it.
- **Starting in Auto turns the sandbox on.** Only Shift+Tab into Auto used to do it. A session
  that opened in Auto — a remembered gear, `--gear auto`, `[permissions] gear = "auto"` — kept a
  saved `off`, and 421 of 421 shell calls on the author's machine between 8 and 16 September ran
  unsandboxed. Your saved `/sandbox` setting is not rewritten; the change lasts for the session. An `off` you
  give for the run itself — `--no-sandbox` or `RUNE_SANDBOX_MODE=off` — still stands.
- **A reviewer that cannot be reached is never a prompt.** With no sandbox under a command, Auto
  asks its safety reviewer; when a free-tier reviewer timed out, Auto used to hand the question
  to you. Now ordinary development work — builds, tests, installs, linters, local git — runs and
  is recorded as unreviewed, as long as nothing in the run looks captured and the command is low
  or medium risk on its own. Background processes, retries of commands the sandbox refused, and
  anything else wait in the end-of-turn list with a plain reason while the agent carries on. A
  timeout also no longer counts toward the rule that halts a run after two reviewer refusals in
  a row.

After this, the only prompts Auto can open mid-run are the ones you configure yourself:
`[permissions.autoMode] askRules` and `unsandboxedShell = "ask"`.

## Measured

- The offline safety corpus (227 scenarios, no model, no network) is unchanged on a contained
  machine: precision 92.8%, recall 89.1%, gate green.
- On an uncontained machine with the reviewer dead — the worst case — 116 of 126 allow rows now
  keep running (79 when everything waits), and 92 of 101 block rows hold. The one given up is a
  reviewer-only row: a test run outside the request's scope, which the corpus never gates
  offline.
- A property test runs every sandbox mode, both isolation states and four reviewer behaviours
  (allow, deny, unreachable, unparseable) over a 28-action stream and fails on any prompt. Each
  new guard was checked by removing it and watching its test fail.

## Platforms

The Windows CI fixes in this release (`cfg` gates for the `-D warnings` lint, path separators,
LF checkouts) change nothing on macOS or Linux. Windows remains a **preview**: there is no OS
sandbox on Windows, so Auto treats every Windows shell command as uncontained. The Windows
spelling of a home path (`C:\Users\<name>`) is not yet recognised by the recursive-delete
breaker; that work is open.

## Unverified, and stated

- Auto's unreviewed path has not been exercised in a live run with a real reviewer outage; it
  is covered by unit tests, the offline corpus and a mutation check of each guard.
- The macOS 27 probe fix was verified on one machine (macOS 27.0, build 26A428). The CI macOS
  runners are older releases, where the named profile still works.
- Some read-only shell shapes are still not recognised as read-only (`iostat`, a `for` loop over
  `sysctl`, `echo "$(test -f …)"`). Inside the sandbox this costs nothing; on an uncontained
  shell it costs a reviewer call.

Everything else is as in v0.1.1.
