# Rune v1.4.16

A patch on v1.4.15. `/connectors` connects services from the session: GitHub, Vercel,
Supabase, Linear, Notion and 27 more, each one's address and sign-in checked by hand, with
pasted tokens kept in your keychain and each connector's settings one screen away.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

**`/connectors`.** It opens on what is connected: each connector's state, how many tools it
gives the agent, and whether it applies in every project or only this one. Below that are the
ways to add one:

- **Four shelves of checked services.** Developer tools (GitHub, Vercel, Supabase, Neon,
  Sentry, Cloudflare, Netlify, Railway, Render, Stripe, PostHog, Prisma, PlanetScale, GitLab,
  Buildkite, Expo, Hugging Face, Postman, Chrome DevTools, Firebase), docs and search (Context7,
  DeepWiki, Microsoft Learn, AWS Knowledge), work and planning (Linear, Notion, Atlassian,
  monday.com, ClickUp, Intercom) and design (Figma, Canva). Each was checked on 2026-10-26 from
  outside, with no credentials: its address answered, and for a browser sign-in its published
  metadata offered everything Rune's sign-in needs.
- **Search everything:** the checked list, the bundled catalog and the public MCP registry
  together, the last two labelled "not checked".
- **By address or command:** any MCP server.

Connecting opens the browser for a sign-in (esc cancels), or asks for a token in a masked
prompt and says where to make one, or connects at once when there is nothing to sign in to. The
connector starts before the screen closes, so its tools are in the next request.

**Each connector's settings:** reconnect, sign in again, replace its token, sign out, the
vendor's own settings where it has them (Supabase read-only and one project, GitHub
read-only), turn off and on, every project or this one only, its tools, and remove. `/mcp`
opens the same screen.

**Pasted tokens stay in the keychain.** GitHub and Render sign in with a token; Context7 takes an
optional one. The token goes to the OS credential store, and the config names where it is
(`${keychain:mcp-token:github}`), never what it is. `rune mcp login github` takes one at the
terminal, hidden, or from a pipe.

**Three sign-in fixes, found checking the vendors:**

- A server built to the 2025-03-26 spec publishes no resource metadata; Rune now signs in at the
  server's own address instead of stopping at "no authorization server advertised".
- A sign-in now asks the server for its sign-in challenge first, the first place the spec says
  to look.
- Signing in again could be refused: the app Rune registered was registered for the previous
  sign-in's temporary port. Rune now registers again when the port has changed.

**Said up front instead of failing at sign-in.** Slack, Asana, PagerDuty and HubSpot accept only
apps they registered themselves. Five entries in the bundled catalog pointed at addresses
Anthropic runs for Claude alone. `/connectors` and `rune mcp add` give the reason. Atlassian's
address moves to `/v2`, the one Atlassian documents.

**A paste into a one-line prompt** with a trailing newline used to arrive as the text "[Pasted
text #1 +2 lines]". It now lands as typed.

## Checked, and stated

The release also pins Zod to 4.6.6, fixing the dependency-audit failure for
[GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).

- **Live, with no credentials:** DeepWiki, Microsoft Learn, AWS Knowledge and Context7 (no key)
  connected through Rune's own discovery, with 3, 3, 5 and 2 tools. Rune's own sign-in discovery
  reached self-registration for Vercel, Supabase, Atlassian and Linear, and found none for GitHub,
  which is why GitHub takes a token.
- **Against a local server that implements the sign-in standards strictly:** an older server
  signs in at its own address; the challenge is asked for and followed; a stale registration is
  replaced and a fixed port keeps its one; a pasted token reaches the server from the keychain,
  and with none stored nothing is sent.
- **15 deliberate breakages, all caught.** One survived at first: the rule that closes a Claude-only
  address was hidden behind the list of closed names. A test now pins it with a name no list
  knows.
- **Suites:** unit 8,183 passed and 0 failed; integration 503 and 0; typecheck and lint 22 of 22.

## Known, and stated

- **Vercel and Figma admit only AI apps they have reviewed,** and Rune is not on either list yet.
  Rune follows their sign-in exactly, but their page may refuse it; `/connectors` says so before
  the browser opens.
- **A browser sign-in has not been run end to end with a real account** for this release; it needs
  a person at the browser. The steps before it were run live against Vercel, Supabase, Atlassian
  and Linear.
- **Connectors start one after another,** so a session with many takes longer to have them all.
