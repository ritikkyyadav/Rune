# Rune v1.4.13

A patch on v1.4.12, found by Rune working on its own source. A run on a project whose tests take
longer than the end-of-turn check's limit can now end `done`, and says what that rests on.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **`done` on a project whose tests run long.** In the dogfood test of 22 October, Rune 1.4.12
  and Codex CLI made the same correct change to Rune's own source, on the same model. Both passed
  the hidden test, 3 of 3. Rune's suite takes about 222 seconds. Its end-of-turn check stopped at
  120 seconds with "nothing was measured", and `done`, which needs a passed check, never came:
  the run ended `unmet — no criteria stated`. Now:
  - a headless run (`rune -P`) gives each check five minutes. An interactive session keeps two,
    since a person waits at the end of every turn that wrote. `[verify] timeoutSecs` still sets
    both;
  - when the suite still does not finish, the test files the change touched, run on their own as
    before, may stand in for it. `done` then says so: "`bun run test` did not finish, and the test
    files the change touched passed in its place". The request check is still asked, and the
    envelope's `verdict.standIns` lists each suite with what stood in for it;
  - the checks after an unfinished one still run. Lint is ordered after the tests, so behind a
    slow suite it never ran at all. A red one there is now a red check.

- **A running background shell is waited on, not treated as a loop.** Rune polled its own long
  test run with `bash_output`, and every answer was "running, no new output". Both loop guards
  read that as a rut: one skipped the poll, the other nudged, and the agent killed a run that was
  only long. A read that finds its shell still running is now a wait. `bash_output` also takes
  `wait_seconds` (up to 300) to wait for a shell to finish in one call. Each poll was a model call
  carrying the whole conversation.

- **The project's format check runs at the end of a turn.** Both agents of the dogfood test left
  a new row of a docs table wider than its column, and CI's format gate refused both trees; Rune
  never ran the format check. A `format:check` script (or a same-named variant) that runs
  `prettier --check` is now a check, run last. A red one is read file by file. Files the run did
  not change were not unformatted by it, so formatting debt you were already carrying buys no
  repair turn. A changed prettier setup, or a file prettier could not parse, leaves the answer
  unknown, and the red is the run's to look at.

- **"Source" is not research.** The intent reader labelled the dogfood task `research` because
  it ended "it is Rune's own source". Sources count now only when asked for as sources: cited,
  found, credible, or sources for something. The label only reached the decision record and the
  title.

## Checked, and stated

- **The dogfood test** (one run each, GPT-6.1 Sol at "high", Rune 1.4.12 against Codex CLI
  0.160.1):

  |                                | Codex CLI             | Rune 1.4.12                  |
  | ------------------------------ | --------------------- | ---------------------------- |
  | Hidden test (404, 410, 401)    | 3 of 3                | 3 of 3                       |
  | Unit, integration, reliability | all green             | all green                    |
  | CI's format check              | fails on `docs/ci.md` | fails on `docs/ci.md`        |
  | The tool's own ending          | says it finished      | `unmet — no criteria stated` |
  | Five-hour quota used           | 7 points              | 17 points                    |

  Codex's 32.6 minutes included one model request that waited 27 minutes for an answer; its other
  turns took about 5½. Rune took 12.6, with no stall. The full record is in the ledger and
  `docs/evidence/dogfood-20261022/`.

- **29 deliberate breakages, all caught**: 12 for the long-suite `done`, 17 for the rest. They
  include `done` resting on a green check that was not the suite's stand-in; a stand-in for some
  other command; a verifier that stops at the timeout again; an unfinished set called a pass; the
  verdict line not naming the suite; the mode read backwards in the CLI; polls of a finished shell
  excused like a running one; and inherited formatting blamed on the run. One survived at first:
  a prettier report that mixed an old unformatted file with a file it could not parse. Read as a
  plain list, it would have filed the run's syntax error as inherited formatting. A test now pins
  it.
- **Through the real engine** (`tests/integration/done-long-suite-e2e.test.ts`). With a suite
  killed at its limit and the change's own test green in its place, the run ended `done` with the
  stand-in named and the request check asked. A change that touched no test file did not. Nor did
  a stand-in that went red.
- **Suites:** unit 8,084 passed and 0 failed; integration 495 and 0; reliability 62 of 62; the
  scripted evaluation 63 of 63; typecheck 15 of 15; lint 7 of 7. One unit test first failed
  because the version was bumped while the suite was running; it passes on the stable tree.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows.

## Known, and stated

- **A headless run on a large project now waits for its suite**, up to five minutes per check at
  the end of a run that changed code, where it gave up at two. On Rune's own source that is about
  two minutes more, and it buys a full measurement.
- **A stand-in is weaker proof than the suite.** It runs only the test files the change touched,
  so a test elsewhere that the change broke is not run. The verdict line names the suite that did
  not finish, so the two kinds of `done` can be told apart.
- **The format check adds its own time** at the end of a turn: about 13 seconds on Rune's own
  source.
- **Not yet shown live.** The fix is measured through the real engine with a scripted model. A
  live re-run of the dogfood task on 1.4.13 has not been done.
- **Not addressed here:** the dogfood test's other finding. Rune used 2.4 times Codex's quota on
  the same change, because each call carries about 51,000 tokens of doctrine and tool schemas.
