# Rune v1.4.6

A patch on v1.4.5, and the fifth phase of the reliability plan: state you can get back. `/rewind`
can now put the files back, a long output is saved whole, and a session that cannot save says so.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **`/rewind` can put the files back, not only the conversation.** Until now it rolled back the
  conversation and left every edit of the rewound turns on disk. Before a turn's first write to a
  file, Rune now keeps what the file held, or that it did not exist.

  | Command            | What it does                                                         |
  | ------------------ | -------------------------------------------------------------------- |
  | `/rewind`          | Lists the turns, with how many files each changed                    |
  | `/rewind <n>`      | Rewinds the conversation, as before, and says if files changed since |
  | `/rewind <n> code` | Puts the files back to how turn n found them                         |
  | `/rewind <n> both` | Both                                                                 |

  A code rewind restores the files the later turns changed and removes the ones they created. What
  is tracked is what Rune's own file tools write: `write_file`, `edit_file`, `multi_edit`,
  `apply_patch`, and a worker's declared files. **A file a shell command changed is not tracked**,
  and every code rewind says so. Snapshots are kept for the last 100 turns of a session and for 30
  days, under `~/.rune/file-history`, and they survive a resume. A file over 5 MB is noted, not
  copied, and a rewind reports it untouched.

- **A long tool output is saved whole.** Output over the transcript's 30,000 characters kept its
  head and tail, and the model was told to re-run the command to see the middle: four minutes of
  test suite to read one stack trace. The whole output is now saved under
  `<workspace>/.rune/outputs/`, and the marker for the missing middle names the file, so the model
  reads it with `read_file`. The folder ignores itself in git, the search tools skip it, and only
  the newest 50 are kept.

- **A full disk no longer stops a session saving in silence.** Every transcript write is
  best-effort, so a full disk, a read-only database or an I/O error dropped messages, and a resume
  later found the conversation short. Now the run says "Recent messages may not be saved for
  resume", with the cause and what fixes it. It says this when writes start failing, again at the
  end of every turn while they do, and once more when saving works again.

- **Compaction that cannot keep up stops instead of looping.** When the context was full again
  within two turns of being compacted, three times running, each compaction was another summary
  call that bought two more turns. The run now ends with a named error and what to change: read
  large files in pages, narrow searches and output, or hand the large output to a sub-agent.

- **The sleep check no longer takes a system time change for a sleep.** 1.4.4's check measured
  gaps on the wall clock alone, so a moved system time looked like the machine had slept, and the
  next failures were re-sent without counting. In CI on Windows, a test that moved the time made
  later runs in the same process re-send three times. A gap now counts only when the monotonic
  clock agrees. On macOS that clock keeps counting through sleep, so a real sleep is still seen;
  on Linux it pauses in suspend, so a sleep there is not seen, as before 1.4.4.

## Checked, and stated

- **The rewind was driven through the real engine.** A scripted model wrote files through the real
  permission check and the real file tools over two turns:
  - `/rewind 2 code` gave back turn 1's version and removed the file turn 2 created;
  - `/rewind 1 code` gave back the original;
  - a write the permission check refused left no snapshot.
- **The saving failure was driven against a real SQLite database put into read-only mode.**
  A constraint error is not treated as a sick database.
- **17 deliberate breakages, all caught.** These included:
  - the latest snapshot used instead of the first;
  - a refused write snapshotted;
  - a conversation rewind keeping snapshots whose turn numbers get reused;
  - no `.gitignore` beside saved output;
  - a two-turn refill not counted as thrash;
  - a recovered database still reported as failing.
- The time-change defect was reproduced on macOS: a test that moves the system time, run before
  the transport tests in the same process, failed four of them with 1.4.4's check and none with
  this one. A test with a real ticking clock now proves a moved time costs a failure as usual.
- **Suites:** unit 7,939 passed and 0 failed; integration 488 and 0; the scripted evaluation 63
  of 63.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows.

## Known, and stated

- **Shell changes are not tracked.** A `sed -i` or a script that writes files is outside the
  snapshots; the rewind says so every time.
- **A sub-agent's own long output is not saved yet**, only the lead's; a sub-agent keeps head and
  tail as before.
- **No live run has exercised these yet**; the live sitting (R8) is where they are measured.
