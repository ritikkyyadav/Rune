# Rune v1.4.14

A patch on v1.4.13, found by Rune's live re-run on its own source. A small change to a long file
is now a small diff, so a run that edits Rune's largest files can end `done`.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **The request check skipped every change to a file over 4,000 lines.** On the live re-run of
  the dogfood task on 1.4.13, every end-of-turn check passed on Rune's own source for the first
  time: the full suite, lint, the format check and typecheck. The request check then skipped
  itself ("the change is larger than the check reads"), and the run ended `unmet`. Above 4,000
  lines the diff gave up and wrote the whole file as removed and added. A 9-line edit to
  `agent-loop.ts` (7,802 lines) was a 737,609-character diff, against the check's cap of 120,000.
  Now:
  - the unchanged start and end of a file are set aside first, so an edit in the middle of a
    long file is a short diff to find;
  - what is left goes to the line table when it is small, and to Myers' diff algorithm when it
    is not: its work grows with the number of changed lines, not with the file's length;
  - past 2,000 changed lines a diff is still one whole-file hunk.

  That edit is now 1,898 characters and 9 lines.

- **The diffs shown for `apply_patch` and `multi_edit` on long files** are their real hunks, not
  the whole file.

## Checked, and stated

- **Six deliberate breakages, all caught.** They include a long middle handed to nobody, a walk
  back that swaps insertions and deletions, a wholesale rewrite left unbounded, an off-by-one in
  the bound, a suffix that overlaps the prefix, and trimmed ends not given back as context.
- **Myers' walk and the line table agree** on 400 seeded random pairs: both rebuild the new text
  exactly, with the same, shortest number of changes.
- **The request check reads a small edit to a 7,802-line file** whole, with room to spare.
- **Suites:** unit 8,090 passed and 0 failed; integration 495 and 0; reliability 62 of 62; the scripted evaluation 63 of 63; typecheck 15 of 15; lint 7 of 7.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows.

## Known, and stated

- **`done` on Rune's own source is not yet shown live.** The re-run on 1.4.13 found this bug; a
  re-run on 1.4.14 is next.
- **A check's limit counts wall-clock time,** so a Mac that sleeps during the end-of-turn check
  turns the sleep into a timeout. Found by the first 1.4.13 re-run, when the lid was closed; not
  addressed here.
- **Cost:** on the same task, Rune 1.4.13 used 55 calls and 4.95 million input tokens, against
  Codex CLI's 1.76 million. Each call still carries about 51,000 tokens of fixed instructions and
  tool definitions.
