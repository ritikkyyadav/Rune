# Rune v1.4.2

The first release of the 1.4 line. It carries two pieces of work: runs that cost less and wait
less, measured against OpenCode on 14 October, and the first phase of a reliability plan, in which
Rune's file tools stop changing what they were not asked to change. The rest of that plan ships in
this line, one phase per patch: 1.4.3, 1.4.4 and on. There was no 1.4.0 or 1.4.1.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

### Files

- **An edit no longer changes what it was not asked to change.** Until this release:
  - every file `edit_file` or `write_file` wrote was left at mode 600, so an edited script lost
    its executable bit and git showed a mode change;
  - one byte that was not UTF-8 was rewritten as U+FFFD;
  - a CRLF file came back with mixed line endings;
  - an edit whose old text had the wrong indentation was applied anyway, to a Python file that
    then failed to parse, and was reported as a success.

  Now a write keeps the file's permissions, line endings and byte-order mark. A file that is not
  UTF-8 is refused with nothing written, and `read_file` says so before an edit is tried.
  `write_file` writes through a symlink instead of replacing it. The same rules hold in
  `multi_edit` and `apply_patch`.

- **Edits match exactly, and a miss says what nearly matched.** The whitespace- and
  indentation-insensitive fallbacks are gone; they had matched 3 of 1,448 recorded edits. A miss
  names the lines that would have matched and what differs, so the next attempt can be right.
  Line endings are the one conversion: old text written with LF still matches a CRLF file.
- **An edit to a file that changed since it was read goes through when it still fits.** That is,
  when the text being replaced is still there exactly once. The result says the file changed.
  `multi_edit` now needs the file read first, as `edit_file` always has.

### Cost and time

- **The end-of-turn check no longer inherits Rune's own state.** For a project whose tests read
  Rune's environment (Rune's own repository is one), the check ran against the live session and
  was killed at its 120 s limit. On the recorded tree it now takes 62 s and passes.
- **A check the run already watched pass is not run again** while the tree is byte-for-byte the
  same. `[verify] reuse = false` turns it off.
- **A check that cannot finish stops being waited for.** For a `bun test` suite, the test files
  the change wrote are run in its place.
- **On Codex, the second request of a run is cached again.** It read 0 cached tokens; it now
  reads 10,368 of a 10.7k prompt. On hosts that cache, the system prompt also stays the same for
  the whole request.
- **The background safety screen runs on the session's model.** Auto mode also no longer takes
  the name of a service in a script for a command that runs it. Replayed over three recorded
  runs, the reviewer's cost went from $0.568 to about $0.08, and the safety corpus still blocks
  and allows exactly what it did.
- **With no browser, Rune no longer asks for a review that cannot see the page.** A headless run
  with nobody to ask is also no longer told to ask, to research or to read back.
- **A headless result says why its verdict is short of met** (`shortfall`).
  `[llm] effortRouting = "task"` is available and off by default.

The full list is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Checked, and stated

- **The file tools.** Six same-input probes
  ([`edit-probes.sh`](../evidence/rune-reliability-probes-20261014/edit-probes.sh)) fail six of
  six against 1.3.4's tools and pass six of six against 1.4.2's. A table of cases runs against
  both the Rust tools and the TypeScript ones: it fails 15 of 19 on the old binary and passes 19
  of 19 on this one. Eight deliberate breakages of the new rules each turned at least one case
  red. Claude Code's own Edit and Write, given the same six inputs, refuse or keep the file intact
  in the same way.
- **Cost and time, live.** Six runs on 14 October, Rune against OpenCode on the same model
  (`gpt-6-sol` on the Codex subscription):
  - small task: Rune took 22 s and 4 model calls ($0.046); OpenCode's two runs took 34 s and 46 s
    ($0.061 and $0.083);
  - hard task: Rune took 313 s ($0.649) and OpenCode 368 s ($0.654), and both passed all 15
    hidden checks.

  Two tasks are not a score.

- **Suites:** unit 7,822 passed and 0 failed; integration 485 and 0; the scripted evaluation 63
  of 63.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows.

## Known, and stated

- **Rune still calls finished work unfinished.** Every live run in the 14 October sitting ended
  "partial" or "unmet" with exit 1, on work that passed every hidden check. `shortfall` says which kind, and
  the exit code is unchanged. Making the exit code say how a run ended is a later 1.4 patch.
- **A quota wall is reported as `provider_lost`.** Of 163 recorded runs since 14 September, 44
  ended `provider_lost`, and 39 of those had hit a Codex usage limit rather than lost the
  provider. They are to be named separately in a later 1.4 patch.
- **`apply_patch` never recorded how its hunks matched before this release.** How often its old
  fallbacks were used is unknown; it reports how each hunk matched now.
- The file-tool changes were checked by tests and probes, not in a live run.
  `effortRouting = "task"` has not been measured for the quality of the work.
- A check still runs outside the sandbox. Only Rune's own variables are removed from its
  environment.
