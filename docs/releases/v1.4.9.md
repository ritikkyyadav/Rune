# Rune v1.4.9

A patch on v1.4.8, and the first phase of the reliability plan, R0: the yardstick. A suite now
drives the real `rune -P` through faults at the wire and signals at four points, and runs in CI.
On its first runs it found three defects, all fixed here.

## Install or upgrade

```sh
curl -fsSL https://savoir.services/install.sh | bash
```

An existing install can run `rune upgrade`.

## What changed

- **A run killed outright no longer leaves its commands running.** Rune runs some commands in a
  process group of their own: the end-of-turn check, hooks, background shells, a worker's check,
  and the parent check's replays. Those groups were stopped by an exit handler, and a `kill -9`,
  a crash or a power cut runs none. Killed during its end-of-turn check, a run left `npm test`
  running with no one waiting for it. Each of these commands now runs under a shell that checks,
  once a second, that the process which started it is alive, and stops its own group when it is
  not. Tool calls through `rune-tools` already did this (S-1, September).
  `RUNE_PARENT_WATCH=off` turns it off.

- **A half answer is no longer kept when Rune sends a request again itself.** The gateway retries
  a failed request three times, and resets the screen before each. When those were spent and the
  run sent the request again itself, it sent no reset. The text the failed attempt had shown stayed
  on screen and in the headless envelope, and the new answer was appended to it: "An answer cut
  afteThe answer, sent again."

- **A stream from an OpenAI-compatible host that ends with no `finish_reason` counts as a cut.** It
  used to be given a synthetic end of turn, so a dropped connection ended a run "finished", with
  exit 0 and a truncated reply. It is now a retryable failure, and the request is sent again.
  Codex and Anthropic streams already said when a response was whole.

- **`bun run reliability`, the yardstick.** `tests/reliability/` drives the real `rune -P` from
  source against a scripted model on a loopback port, with a scratch home and no credentials:
  - **transport:** a response cut mid-stream, a stream that goes quiet, a malformed event, a 529
    with `Retry-After`, a refused key, and the wall clock set an hour forward;
  - **process:** SIGTERM, SIGINT and SIGKILL while the model answers, while a tool runs, while a
    compaction summarises and while the end-of-turn check runs, plus a SIGKILL while a background
    shell runs. A resume has to finish every one.

  CI runs it on macOS and Linux, and its transport half on Windows. The contract suite
  (`edit-probes.sh` as tests) already ran in the unit and integration steps.

- **[`docs/errors.md`](../errors.md)**, what Rune says when something fails, what it does on its
  own, what is left for you, and the test that pins each row.

## Checked, and stated

- **The suites, through the real process:** transport 6 of 6, process 13 of 13, in 162 s on
  this Mac.
- **14 deliberate breakages, all caught:**
  - the loop's new reset: removed at each of its three sites, the flag never set, and a reset
    sent always;
  - the parent watch: one that never kills, one never stopped when the command ends, no wrapper
    at all, the argv unquoted, the exit status dropped, and a watch on its own shell instead of
    its starter;
  - through the real process, the verifier's check and the background shells each started
    unwatched: the process suite saw both left running after a SIGKILL;
  - 1.4.4's wall-only sleep clock, put back: the clock-jump test reported the hour as a sleep.
- **Two of those first passed when they should not have, and the tests were fixed.** With a
  single cut, the gateway's own retry absorbed it and the clock-jump test never reached the
  loop's sleep check, so it passed against the broken clock; it now cuts four times. The
  unquoted-argv breakage was caught only by a timeout, because a failing assertion left the
  test's helper process holding the pipe; the test now cleans up in `finally`.
- **A false alarm, stated.** On 19 October two spawn-site tests seemed to hang for 1,000 s and
  225 s. The Mac was in clamshell sleep for exactly those windows (`pmset -g log`). Awake, the
  same 24 files pass 699 of 699 in 67 s.
- **Suites:** unit 7,964 passed, 19 skipped and 0 failed in a fresh clone of the release commit;
  integration 488 and 0; the scripted evaluation 63 of 63; Rust 142 and 0; typecheck 15 of 15;
  lint 7 of 7.
- This release was tagged only after CI passed on its own commit: macOS, Linux and Windows,
  including the new Windows job.

## Known, and stated

- **Windows.** The process suite skips itself there: Windows has no SIGTERM or SIGINT to send a
  process. A command started in its own group is not watched there either; there is no group to
  kill.
- **A run's `durationMs` reads the wall clock**, so a clock change shows in it.
- **R2.2's "keep the finished calls" needs a host that says when each call is finished** (Codex,
  Anthropic). The OpenAI-compatible adapter finishes calls only at `finish_reason`, so a cut there
  sends the whole response again.
- **The watch polls once a second.** A command can outlive a killed run by up to a second, and
  the watch's last `sleep 1` can outlive a finished command by as long.
- **A retired model ends a run `provider_lost`.** The message names the cause and the fix; the
  label does not.
- **A stall before the first byte is not driven by the suite.** It is the same watchdog with a
  120-second allowance, and the suite drives the 45-second one between chunks.
