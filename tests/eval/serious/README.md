# The serious family (F7)

Real fixes mined from this repository's history, graded SWE-bench style. An arm
starts from the PARENT tree of a fix commit, gets a prompt written like an issue
someone filed, and is graded by the fix commit's own tests, which it never sees.
The method, the validation rules and the task list are in
`docs/program/serious-corpus.md`.

## Files

| File               | What it does                                                                                                                                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mine.ts`          | The CLI: lists candidates, validates them, prints prompt-writer dossiers, writes `tasks/<sha>.json`, checks every task file.                                                                                                                |
| `f2p.ts`           | Validates one candidate: the hidden tests twice at the parent and twice with the fix, sorted into fail-to-pass, pass-to-pass, impossible, flaky and skipped.                                                                                |
| `grade.ts`         | The one test runner the miner and the grader share (bun's JUnit report, a scratch HOME, no credentials), and the `Outcome` of a graded tree.                                                                                                |
| `source.ts`        | The `ParityTask` adapter over `tasks/*.json`: `prepare` builds the parent tree with no history, `grade` copies the hidden tests over whatever the arm left and scores it.                                                                   |
| `leak.ts`          | The leak check: a prompt may not name anything the fix added (a declaration, a new field, a string literal of 12+ characters) unless the hidden tests use it, and each `interface` entry must be used by the tests and named in the prompt. |
| `tasks/<sha>.json` | One task each: the commit and its parent, the prompt, the checks, the typecheck record, the hidden files and the fix files. Generated by `write-tasks`; the prompt is the hand-written part.                                                |

Unit tests: `tests/unit/eval/serious-{mine,f2p,grade,leak,source}.test.ts`. The last
block of `serious-source.test.ts` checks the committed corpus itself: at least 25
tasks with the three seeds, every file well formed, stratified over packages and
shapes, and (when the history is present) no prompt leaking its fix.

## Commands

Nothing here calls a model.

```sh
# How many commits qualify, before running anything.
bun tests/eval/serious/mine.ts candidates

# Validate candidates, at most three at a time. Results land in --out
# (default $TMPDIR/serious-mining), one directory per commit; --force redoes one.
bun tests/eval/serious/mine.ts validate --jobs 3 [--only sha,sha] [--out DIR]

# What a prompt writer needs for each kept candidate: the commit message, the
# hidden test diff, the checks, and the new names to keep out of the prompt.
bun tests/eval/serious/mine.ts dossier --out FILE [--mined DIR] [--only sha,sha]

# Join hand-written prompts ({ "<sha>": { slug, shape, prompt, interface? } })
# with the mining results into tasks/<sha>.json, formatted for the repo's
# prettier gate.
bun tests/eval/serious/mine.ts write-tasks --prompts FILE [--mined DIR]

# Every task file: well formed, no leak, interface used and named. Exit 1 on any problem.
bun tests/eval/serious/mine.ts check
```

A task as a `ParityTask`:

```ts
import { seriousTasks } from "./tests/eval/serious/source";
const [task] = seriousTasks(); // id order; family "F7", size "serious"
await task.prepare(workspace); // the parent tree, installed, committed as "base"
const outcome = await task.grade(workspace, evidenceDir); // writes grade.json there
```

## Adding a task

1. `validate` the commit (or find it kept in an existing mining run).
2. Read its `dossier`. Write the prompt as a symptom a user would file: what goes
   wrong and how to see it, then what should happen, then the constraints (existing
   exports keep working, existing tests keep passing). Add an "Interface the fix
   must provide" section only for what the hidden tests call and the parent lacks
   — a symbol, a new parameter or field, a new module — and list those entries in
   `interface`. Never describe the implementation.
3. `write-tasks`, then `check`. A task that leaks is reworded or dropped, never
   committed. Then run the unit tests above.
4. Add the task to the table in `docs/program/serious-corpus.md`, with why it was
   chosen, and date the change in its Changes section.
